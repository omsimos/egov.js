# Choose an eGov service

**Nine service clients** share one transport and error model while preserving
each provider's authentication and response types.

| Service                              | Primary capability                         | Authentication                            | Writes or side effects           |
| ------------------------------------ | ------------------------------------------ | ----------------------------------------- | -------------------------------- |
| [eGov AI](./egov-ai.mdx)             | Generate, translate, and extract content   | Access code, then bearer token            | Consumes credits                 |
| [eGov Compass](./egov-compass.mdx)   | Query budget records and dashboards        | API key                                   | None                             |
| [eGovChain](./egov-chain.mdx)        | Use EVM-compatible JSON-RPC                | None                                      | Raw transactions write to chain  |
| [eGovPay](./egov-pay.mdx)            | Create, inspect, and void payments         | API key and settlement template           | Changes payment state            |
| [eGov SSO](./egov-sso.mdx)           | Exchange login codes and retrieve profiles | Partner code and secret                   | Creates tokens and processes PII |
| [eMessage](./emessage.mdx)           | Send SMS messages                          | Access token                              | Sends messages                   |
| [eReport](./ereport.mdx)             | Submit and view citizen reports            | Access code, bearer token, and view token | Submits complaints and OTPs      |
| [eVerify](./everify.mdx)             | Verify identities and QR payloads          | Client credentials                        | Processes identity data          |
| [Face Liveness](./face-liveness.mdx) | Create biometric verification sessions     | API key                                   | Starts biometric sessions        |

<Warning>
  Documented and example hosts, including the default eGovChain RPC, are **partner staging or
  hackathon systems**. Access is governed by provider agreements and credentials.
</Warning>

runtime discovery of supported paths, methods, and expected status codes.
