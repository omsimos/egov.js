# eReport public API reference

The eReport client submits citizen complaints, reads authenticated reference
datasets, performs email OTP verification, and retrieves reports. There is no
default base URL: pass the eReport deployment URL supplied for your integration.

**Imports**

Runtime factories, the catalog, and the runtime API object are exported from
`egov.js/eReport`:

```ts
import {
  EREPORT_SOURCE_URL,
  createEReportClient,
  createEReportClientFromEnv,
  eReportApi,
  eReportCatalog,
} from "egov.js/eReport";
```

eReport interfaces and type aliases are exported from the dedicated
`egov.js/eReport/types` subpath, not from `egov.js/eReport`:

```ts
import type {
  EReportClient,
  EReportClientOptions,
  EReportConfirmOtpRequest,
  EReportConfirmOtpResponse,
  EReportDatasetListResponse,
  EReportDatasetRecord,
  EReportEnvironmentClient,
  EReportEnvironmentClientOptions,
  EReportGenerateTokenResponse,
  EReportListReportsQuery,
  EReportLocationAttributes,
  EReportPagination,
  EReportRecord,
  EReportReportResponse,
  EReportReportsResponse,
  EReportReportTypeAttributes,
  EReportRequestOtpResponse,
  EReportSubmitComplaintRequest,
  EReportSubmitComplaintResponse,
} from "egov.js/eReport/types";
import type { EgovCallOptions, EgovEnvironment, EgovFetch } from "egov.js/core";
```

The types describe the expected provider payloads at compile time. The SDK does
not validate successful response bodies at runtime.

**Credential stages**

eReport uses three distinct credentials. Do not interchange them.

| Credential               | Source                                                                | Sent as                         | Used by                                                           |
| ------------------------ | --------------------------------------------------------------------- | ------------------------------- | ----------------------------------------------------------------- |
| Access code              | Integration configuration, or `EREPORT_ACCESS_TOKEN` with `fromEnv()` | JSON field `access_code`        | `generateToken()` only                                            |
| Integration bearer token | `generateToken().access_token`                                        | `Authorization: Bearer <token>` | Dataset reads, complaint submission, and OTP request/confirmation |
| Report-view token        | `confirmOtp().report_view_token`                                      | `X-EReport-View-Token: <token>` | Report listing and individual report retrieval                    |

<Warning>
  `EREPORT_ACCESS_TOKEN` is a naming exception. Its value is an access code, not the integration
  bearer token returned by the API. `fromEnv()` sends the value in the `access_code` request field.
</Warning>

**Factories**

| Export                       | Kind                  | Purpose                                                                |
| ---------------------------- | --------------------- | ---------------------------------------------------------------------- |
| `createEReportClient`        | Factory               | Create a direct client whose `generateToken()` accepts an access code  |
| `createEReportClientFromEnv` | Factory               | Create a client with `generateToken()` bound to `EREPORT_ACCESS_TOKEN` |
| `eReportApi`                 | Frozen runtime object | Group `create`, `fromEnv`, and `catalog`                               |
| `eReportCatalog`             | Catalog               | Describe the eleven eReport HTTP endpoints                             |
| `EREPORT_SOURCE_URL`         | Constant              | Link to the government API catalog source                              |

**`createEReportClient`**

**Signature**

```ts
createEReportClient(options: EReportClientOptions): EReportClient
```

`eReportApi.create` is the same function.

**Options**

| Field     | Type          | Required | Behavior                                                        |
| --------- | ------------- | -------- | --------------------------------------------------------------- |
| `baseUrl` | `string`      | Yes      | Base URL used to resolve every endpoint path                    |
| `fetch`   | `EgovFetch`   | No       | Fetch-compatible implementation; defaults to `globalThis.fetch` |
| `headers` | `HeadersInit` | No       | Default headers merged into every request                       |

The factory performs no network request. The direct client requires an explicit
access code when calling `generateToken(accessCode, options?)`.

**`createEReportClientFromEnv`**

**Signature**

```ts
createEReportClientFromEnv(
  options: EReportEnvironmentClientOptions,
): EReportEnvironmentClient
```

`eReportApi.fromEnv` is the same function.

**Options**

| Field                      | Type                  | Required                                  | Behavior                                                           |
| -------------------------- | --------------------- | ----------------------------------------- | ------------------------------------------------------------------ |
| `baseUrl`                  | `string`              | Yes                                       | Base URL used to resolve every endpoint path                       |
| `fetch`                    | `EgovFetch`           | No                                        | Fetch-compatible implementation; defaults to `globalThis.fetch`    |
| `headers`                  | `HeadersInit`         | No                                        | Default headers merged into every request                          |
| `env`                      | `EgovEnvironment`     | No                                        | Explicit environment map from which `EREPORT_ACCESS_TOKEN` is read |
| `env.EREPORT_ACCESS_TOKEN` | `string \| undefined` | No at the type level; required at runtime | Trimmed and bound to the `access_code` body field                  |

The factory reads and trims `EREPORT_ACCESS_TOKEN` immediately. If `env` is not
provided, resolution uses `Bun.env` when available, then `process.env`, then an
empty object. A missing, empty, or whitespace-only value throws:

```text
Missing required eGov environment variable: EREPORT_ACCESS_TOKEN
```

The returned client changes only the `generateToken` signature. Every other
method still requires the appropriate integration or report-view token.

**Call options and errors**

Every client method accepts an optional final `options?: EgovCallOptions`
parameter.

| Field     | Type          | Required | Behavior                                      |
| --------- | ------------- | -------- | --------------------------------------------- |
| `headers` | `HeadersInit` | No       | Per-call headers merged over factory defaults |
| `signal`  | `AbortSignal` | No       | Forwarded to `fetch` for cancellation         |

Authentication helpers set `Authorization` or `X-EReport-View-Token` after
reading per-call headers, so a caller-supplied value for the method's required
authentication header is replaced by the token argument. JSON bodies receive
`Content-Type: application/json` unless a content type is already configured.
`Accept: application/json` is added unless already configured.

The catalog declares HTTP `200` for every eReport endpoint. The transport treats
any HTTP `2xx` response as successful and returns its parsed body without schema
validation. Any non-`2xx` response throws `EgovApiError` with `body`, `headers`,
`method`, `status`, `statusText`, and `url`. JSON and `+json` error bodies are
parsed; other bodies remain text, and empty bodies become `undefined`. Fetch
failures and aborts propagate from the configured `fetch` implementation. The
SDK does not automatically retry any request. A response body's numeric `code`
field is provider data and is separate from the HTTP status.

**Workflow order**

A typical complaint and report-viewing workflow is:

1. Exchange the access code for an integration bearer token.
2. Read report types and the region, province, municipality, and barangay hierarchy with that bearer token.
3. Submit the complaint with codes selected from those authenticated datasets.
4. Request an OTP for the complainant email.
5. Confirm the OTP to obtain a report-view token.
6. List the verified user's available reports, then retrieve a report by case number.

```ts
import { eReportApi } from "egov.js/eReport";

const reports = eReportApi.fromEnv({
  baseUrl: "https://your-ereport-deployment.example",
});

const { access_token: integrationToken } = await reports.generateToken();

const reportTypes = await reports.listReportTypes(integrationToken);
const regions = await reports.listRegions(integrationToken);
const provinces = await reports.listProvinces(integrationToken, "040000000");
const municipalities = await reports.listMunicipalities(integrationToken, "042100000");
const barangays = await reports.listBarangays(integrationToken, "042111000");

const reportType = reportTypes.data[0];
if (!reportType) throw new Error("No eReport types are available");

const complaint = await reports.submitComplaint(integrationToken, {
  barangayCode: "042111011",
  complainantEmail: "citizen@example.com",
  firstName: "Juan",
  gender: "Male",
  lastName: "Dela Cruz",
  message: "Streetlight has been out for three nights.",
  mobile: "639171234567",
  municipalityCode: "042111000",
  provinceCode: "042100000",
  regionCode: "040000000",
  reportType: reportType.attributes.code,
  subject: "Broken streetlight",
});

await reports.requestOtp(integrationToken, "citizen@example.com");
const verification = await reports.confirmOtp(integrationToken, {
  email: "citizen@example.com",
  otp: "123456",
});

const history = await reports.listReports(verification.report_view_token, {
  limit: 20,
  page: 1,
});
const report = await reports.getReport(verification.report_view_token, complaint.case_number);
```

`reportTypes`, `regions`, `provinces`, `municipalities`, `barangays`, `history`,
and `report` are shown as separate values because each response retains its
provider-defined metadata and open record fields.

<Warning>
  `submitComplaint()` creates an external complaint record and has no SDK idempotency key. A blind
  retry can create a duplicate. `requestOtp()` sends email, and repeated requests can send multiple
  messages or encounter provider rate limits. Do not automatically retry `confirmOtp()` either: OTP
  expiry, reuse, and attempt limits are provider-controlled. Reconcile outcomes before retrying.
</Warning>

The following order matches the client object in `src/eReport/api.ts`.

## `confirmOtp`

**Signature**

Direct client:

```ts
directClient.confirmOtp(
  integrationToken: string,
  request: EReportConfirmOtpRequest,
  options?: EgovCallOptions,
): Promise<EReportConfirmOtpResponse>
```

Environment client:

```ts
envClient.confirmOtp(
  integrationToken: string,
  request: EReportConfirmOtpRequest,
  options?: EgovCallOptions,
): Promise<EReportConfirmOtpResponse>
```

**Parameters**

| Parameter or field | Type                       | Required | Wire name and location                                            |
| ------------------ | -------------------------- | -------- | ----------------------------------------------------------------- |
| `integrationToken` | `string`                   | Yes      | `Authorization: Bearer <integrationToken>` header                 |
| `request`          | `EReportConfirmOtpRequest` | Yes      | JSON request body                                                 |
| `request.email`    | `string`                   | Yes      | `email` body field                                                |
| `request.otp`      | `string`                   | Yes      | `otp` body field                                                  |
| `options`          | `EgovCallOptions`          | No       | Final call options                                                |
| `options.headers`  | `HeadersInit`              | No       | Additional HTTP headers; cannot replace the bearer token argument |
| `options.signal`   | `AbortSignal`              | No       | Fetch cancellation signal                                         |

The SDK does not validate email syntax, OTP length, or OTP format.

**Returns**

`Promise<EReportConfirmOtpResponse>` resolves to:

| Field               | Type     | Required | Description                                 |
| ------------------- | -------- | -------- | ------------------------------------------- |
| `code`              | `number` | Yes      | Provider response code                      |
| `expires_at`        | `string` | Yes      | Provider-formatted report-view token expiry |
| `report_view_token` | `string` | Yes      | Token for `listReports()` and `getReport()` |

**Behavior/Errors**

Sends `POST /api/integration/verify/confirm` with integration bearer
authentication. The catalog declares HTTP `200`; the transport accepts any
`2xx`. Confirmation produces a distinct report-view token and does not replace
the integration token. OTP expiry, reuse rules, and failed-attempt limits are
provider-controlled, so do not blindly retry a failed or ambiguous confirmation.
Non-`2xx` responses throw `EgovApiError`; fetch and abort errors propagate.

| `options`          | `EgovCallOptions` | No                 | Final call options; first argument on the environment client |
| `options.headers`  | `HeadersInit`     | No                 | Additional HTTP headers                                      |

**Returns**

`Promise<EReportGenerateTokenResponse>` resolves to:

| Field          | Type     | Required | Description                                                       |
| -------------- | -------- | -------- | ----------------------------------------------------------------- |
| `access_token` | `string` | Yes      | Integration bearer token for authenticated integration operations |
| `expires_at`   | `string` | Yes      | Provider-formatted integration token expiry                       |

**Behavior/Errors**

Sends `POST /api/integration/token` and serializes the access code as
`{"access_code":"..."}`. The catalog declares HTTP `200`; the transport
accepts any `2xx`. The SDK does not validate the access code or expiry string and
does not refresh or cache the returned token. Non-`2xx` responses throw
`EgovApiError`; fetch and abort errors propagate. With `fromEnv()`, a missing
access code fails during client creation, before this method can be called.

**Parameters**

| Parameter or field | Type              | Required | Wire name and location                                                 |
| ------------------ | ----------------- | -------- | ---------------------------------------------------------------------- |
| `reportViewToken`  | `string`          | Yes      | `X-EReport-View-Token` header                                          |
| `caseNumber`       | `string`          | Yes      | `{case_number}` path segment, encoded with `encodeURIComponent`        |
| `options`          | `EgovCallOptions` | No       | Final call options                                                     |
| `options.headers`  | `HeadersInit`     | No       | Additional HTTP headers; cannot replace the report-view token argument |
| `options.signal`   | `AbortSignal`     | No       | Fetch cancellation signal                                              |

For example, `PFM/001` is sent as the path segment `PFM%2F001`.

**Returns**

`Promise<EReportReportResponse>` resolves to this open record shape:

| Field               | Type            | Required         | Description                                       |
| ------------------- | --------------- | ---------------- | ------------------------------------------------- |
| `data`              | `EReportRecord` | Yes              | Report object                                     |
| `data.case_number`  | `string`        | No               | Case number when present                          |
| Other `data` fields | `unknown`       | Provider-defined | `EReportRecord` extends `Record<string, unknown>` |

**Behavior/Errors**

Sends `GET /api/integration/reports/{case_number}` with report-view token
authentication. This is an authenticated report read, not a public dataset. The
catalog declares HTTP `200`; the transport accepts any `2xx`. The SDK does not
validate the case-number format or response fields. Non-`2xx` responses,
including provider authorization or not-found responses, throw `EgovApiError`
with the actual status; the catalog does not enumerate those error statuses.
Fetch and abort errors propagate.
