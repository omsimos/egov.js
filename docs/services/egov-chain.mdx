# eGovChain API reference

`egov.js/eGovChain` provides an EVM-compatible JSON-RPC client for the public
eGov hackathon chain. The module has eight named RPC helpers, a generic
`request` method, endpoint metadata, and the complete 70-entry portal catalog.
No credentials are added by the client.

```ts
import {
  EGOV_CHAIN_ID,
  EgovChainRpcError,
  createEgovChainClient,
  eGovChainApi,
  egovChainCatalog,
} from "egov.js/eGovChain";
import { EgovApiError } from "egov.js/core";

const chain = eGovChainApi.create();
const chainIdHex = await chain.chainId();

console.log({
  expectedDecimalChainId: EGOV_CHAIN_ID,
  actualDecimalChainId: Number(BigInt(chainIdHex)),
});
```

**Factory reference**

**`createEgovChainClient`**

**Signature**

```ts
function createEgovChainClient(options?: EgovChainClientOptions): EgovChainClient;
```

The source implementation uses `options = {}`.

**Parameters**

| Parameter         | Type                     | Optional | Default              | Description                                                          |
| ----------------- | ------------------------ | -------- | -------------------- | -------------------------------------------------------------------- |
| `options`         | `EgovChainClientOptions` | Yes      | `{}`                 | Transport configuration.                                             |
| `options.baseUrl` | `string`                 | Yes      | `EGOV_CHAIN_RPC_URL` | JSON-RPC base URL. Requests use its `/` path.                        |
| `options.fetch`   | `EgovFetch`              | Yes      | `globalThis.fetch`   | Fetch-compatible implementation captured when the client is created. |
| `options.headers` | `HeadersInit`            | Yes      | None                 | Default headers copied into every request.                           |

`EgovFetch` has this core signature:

```ts
type EgovFetch = (input: RequestInfo | URL, init?: RequestInit) => Promise<Response>;
```

**Returns**

An `EgovChainClient` with the nine methods in this reference. Creating a client
does not perform a network request.

**Behavior**

Each method sends one `POST` request with a JSON body to the configured base
URL. Factory headers are copied first and per-call headers overwrite matching
names. The transport supplies `accept: application/json` and
`content-type: application/json` only when those headers are absent. It does not
add credentials or retry requests.

**`eGovChainApi` and `eGovChainApi.create`**

**Signature**

```ts
const eGovChainApi: Readonly<{
  catalog: typeof egovChainCatalog;
  create: typeof createEgovChainClient;
}>;

eGovChainApi.create(options?: EgovChainClientOptions): EgovChainClient;
```

**Parameters**

`eGovChainApi.create` accepts the same `EgovChainClientOptions` and defaults as
`createEgovChainClient`.

**Returns**

The same `EgovChainClient` returned by `createEgovChainClient`.

**Behavior**

`eGovChainApi` is shallowly frozen with `Object.freeze`. Its `create` property
is the `createEgovChainClient` function, and its `catalog` property is the same
object exported as `egovChainCatalog`.

**Shared call behavior**

The final `options` parameter on every named helper is:

```ts
interface EgovCallOptions {
  headers?: HeadersInit;
  signal?: AbortSignal;
}
```

`headers` override factory headers by name for that request. `signal` is passed
to `fetch`; abort and other fetch failures propagate unchanged. Only
[`request`](#request) extends these options with a caller-selected
JSON-RPC `id`.

Every call sends this JSON-RPC 2.0 envelope:

```ts
{
  id: number | string,
  jsonrpc: "2.0",
  method: string,
  params: readonly unknown[]
}
```

Automatic numeric IDs begin at `1` for each client and increment only for calls
that do not provide an explicit `request` ID. The client always includes an ID,
so it does not send JSON-RPC notifications.

**Method reference**

## `blockNumber`

**Signature**

```ts
blockNumber(options?: EgovCallOptions): Promise<string>;
```

**Parameters**

| Parameter | Type              | Optional | Default | Description                                          |
| --------- | ----------------- | -------- | ------- | ---------------------------------------------------- |
| `options` | `EgovCallOptions` | Yes      | None    | Final call options: per-call `headers` and `signal`. |

**Returns**

`Promise<string>`, resolving to the current block number as an EVM hex quantity,
for example `"0x1a"`.

**Behavior**

Calls `eth_blockNumber` with `params: []`. It reads chain state and has no chain
write side effect. A JSON-RPC error on an HTTP-successful response throws
`EgovChainRpcError`; a non-2xx HTTP response throws `EgovApiError`; fetch and
abort errors propagate unchanged.

## `call`

**Signature**

```ts
call<TResult = string>(
  transaction: Record<string, unknown>,
  block?: string,
  options?: EgovCallOptions,
): Promise<TResult>;
```

**Parameters**

| Parameter     | Type                      | Optional | Default    | Description                                                               |
| ------------- | ------------------------- | -------- | ---------- | ------------------------------------------------------------------------- |
| `transaction` | `Record<string, unknown>` | No       | None       | Transaction-call object forwarded unchanged as the first RPC parameter.   |
| `block`       | `string`                  | Yes      | `"latest"` | Block tag or block-number quantity forwarded as the second RPC parameter. |
| `options`     | `EgovCallOptions`         | Yes      | None       | Final call options: per-call `headers` and `signal`.                      |

**Returns**

`Promise<TResult>`. `TResult` defaults to `string`, which represents the
`eth_call` return bytes as hex data. A caller-selected `TResult` is an unchecked
TypeScript cast; the response is not decoded or validated.

**Behavior**

Calls `eth_call` with `params: [transaction, block]`. It simulates execution at
the selected block and does not persist contract state, even when the encoded
call targets a state-changing function. The SDK does not ABI-encode the request
or decode the result. A JSON-RPC error on an HTTP-successful response throws
`EgovChainRpcError`; a non-2xx HTTP response throws `EgovApiError`; fetch and
abort errors propagate unchanged.

## `request`

**Signature**

```ts
request<TResult, TParams extends readonly unknown[] = readonly unknown[]>(
  method: string,
  params?: TParams,
  options?: EgovCallOptions & { id?: EgovChainRpcId },
): Promise<TResult>;
```

**Parameters**

| Parameter         | Type                                        | Optional | Default                | Description                                                          |
| ----------------- | ------------------------------------------- | -------- | ---------------------- | -------------------------------------------------------------------- |
| `method`          | `string`                                    | No       | None                   | JSON-RPC method name. It is not restricted to the catalog.           |
| `params`          | `TParams`                                   | Yes      | `[]`                   | Positional JSON-RPC parameters. The tuple type is compile-time only. |
| `options`         | `EgovCallOptions & { id?: EgovChainRpcId }` | Yes      | None                   | Final call options plus an optional JSON-RPC ID.                     |
| `options.headers` | `HeadersInit`                               | Yes      | None                   | Per-call headers that override factory headers by name.              |
| `options.signal`  | `AbortSignal`                               | Yes      | None                   | Signal passed to `fetch`.                                            |
| `options.id`      | `EgovChainRpcId`                            | Yes      | Next automatic integer | A `number` or `string` JSON-RPC ID.                                  |

**Returns**

`Promise<TResult>`, resolving to the response's `result` property. `TResult` is
required or contextually inferred and is an unchecked compile-time assertion;
the method does not associate RPC names with parameter or result types.

**Behavior**

Calls the supplied `method` with the supplied `params`. It can invoke reads,
node-local mutations such as filter creation, or chain writes such as
`eth_sendRawTransaction`; **the generic request method is not read-only**. The
catalog is metadata, not an allowlist, so any method accepted by the configured
node can be requested. A JSON-RPC error on an HTTP-successful response throws
`EgovChainRpcError`; a non-2xx HTTP response throws `EgovApiError`; fetch and
abort errors propagate unchanged.

## `sendRawTransaction`

**Signature**

```ts
sendRawTransaction(
  signedTransaction: string,
  options?: EgovCallOptions,
): Promise<string>;
```

**Parameters**

| Parameter           | Type              | Optional | Default | Description                                                  |
| ------------------- | ----------------- | -------- | ------- | ------------------------------------------------------------ |
| `signedTransaction` | `string`          | No       | None    | Signed, serialized transaction hex data forwarded unchanged. |
| `options`           | `EgovCallOptions` | Yes      | None    | Final call options: per-call `headers` and `signal`.         |

**Returns**

`Promise<string>`, resolving to the transaction hash as fixed-length hex data
when the node accepts the submission. A hash is not a receipt or confirmation.

**Behavior**

Calls `eth_sendRawTransaction` with `params: [signedTransaction]`. It broadcasts
a signed transaction and can change chain state if the transaction is mined.
The SDK does not sign, serialize, estimate gas, choose a nonce, manage private
keys, wait for a receipt, or track confirmations. A JSON-RPC error on an
HTTP-successful response throws `EgovChainRpcError`; a non-2xx HTTP response
throws `EgovApiError`; fetch and abort errors propagate unchanged.

<Warning>
  `sendRawTransaction` writes through a named helper, but [`request`](#request) can perform the same
  write by calling `eth_sendRawTransaction` directly. Verify the RPC URL and chain ID, keep private
  keys and signed payloads out of logs, and design retries to avoid duplicate submissions.
</Warning>

**Errors**

**`EgovChainRpcError`**

```ts
class EgovChainRpcError extends Error {
  readonly code: number;
  readonly data: unknown;
  readonly id: EgovChainRpcId | null;

  constructor(response: EgovChainRpcFailure);
}
```

For an HTTP-successful parsed response with a top-level `error` property, every
client method throws `EgovChainRpcError`. Its fields are copied from the
JSON-RPC failure envelope:

| Field     | Type                          | Source                                                 |
| --------- | ----------------------------- | ------------------------------------------------------ |
| `name`    | `"EgovChainRpcError"`         | Set by the constructor.                                |
| `message` | `string`                      | `response.error.message`                               |
| `code`    | `number`                      | `response.error.code`                                  |
| `data`    | `unknown`                     | `response.error.data`; it is `undefined` when omitted. |
| `id`      | `number`, `string`, or `null` | `response.id`                                          |

`EgovChainRpcError` is distinct from `EgovApiError`:

| Failure stage                                             | Error                              | Fields                                                                                          |
| --------------------------------------------------------- | ---------------------------------- | ----------------------------------------------------------------------------------------------- |
| The server returns a non-2xx HTTP status.                 | `EgovApiError` from `egov.js/core` | `body`, `headers`, `method`, `status`, `statusText`, `url`, plus inherited `message` and `name` |
| HTTP succeeds and the JSON-RPC envelope contains `error`. | `EgovChainRpcError`                | `code`, `data`, `id`, plus inherited `message` and `name`                                       |
| Fetch rejects or the signal aborts.                       | Original runtime error             | Propagated unchanged.                                                                           |

HTTP status handling occurs first. A non-2xx response therefore throws
`EgovApiError` even if its body resembles a JSON-RPC failure.

```ts
try {
  await chain.request("unsupported_method");
} catch (error) {
  if (error instanceof EgovChainRpcError) {
    console.error(error.code, error.message, error.data, error.id);
  } else if (error instanceof EgovApiError) {
    console.error(error.status, error.statusText, error.body);
  }
}
```

**Hex values and unchecked types**

The SDK preserves JSON-RPC strings exactly. It does not parse, normalize, or
validate addresses, block selectors, quantities, byte data, transaction
objects, filters, or response objects.

| Format         | Convention                                                                                                   | Examples in this client                                                                                         |
| -------------- | ------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| Hex quantity   | `0x`-prefixed integer with no leading zeroes, except zero is `0x0`. Convert losslessly with `BigInt(value)`. | `blockNumber()`, `chainId()`, `getBalance()`                                                                    |
| Hex data       | `0x`-prefixed bytes with two hex digits per byte; leading zero bytes are significant.                        | Default `call()` result, signed transaction input, transaction hash output, addresses and hashes inside objects |
| Block selector | A tag such as `"latest"` or a hex block-number quantity.                                                     | `call(..., block)` and `getBalance(..., block)`; both default to `"latest"`                                     |

Do not compare `chainId()` directly with `EGOV_CHAIN_ID`: one is a hex string and
the other is a decimal number. Compare `BigInt(await chain.chainId())` with
`BigInt(EGOV_CHAIN_ID)` or encode the constant as hex first.

The transport casts the parsed HTTP body to its requested TypeScript type. The
chain client then checks only whether the top-level response has an `error`
property and otherwise returns `response.result`. It does not validate
`jsonrpc`, `id`, `result`, or the error shape. Consequently:

- `call<TResult>`, `getLogs<TResult>`, and `request<TResult, TParams>` generics
  provide compile-time assertions only.
- `TParams` does not validate a method's parameter tuple or connect it to
  `TResult`.
- `Record<string, unknown>` transaction and filter inputs are forwarded without
  runtime checks.
- A malformed server response can produce an incorrectly typed value or a
  native JavaScript error instead of an SDK error.

**Public types**

`egov.js/eGovChain` and `egov.js/eGovChain/types`:

type EgovChainRpcId = number | string;

  code: number;

`EgovChainClient` is the interface containing the nine exact method signatures

not re-exports of the `egov.js/eGovChain` subpath.

**`egovChainCatalog`**

`egovChainCatalog` is the runtime catalog object also exposed as
`eGovChainApi.catalog`. Its service metadata is:

| Field              | Value                                                         |
| ------------------ | ------------------------------------------------------------- |
| `id`               | `"egovchain"`                                                 |
| `name`             | `"eGovChain"`                                                 |
| `slug`             | `"egovchain"`                                                 |
| `sourceUrl`        | `EGOV_CHAIN_SOURCE_URL`                                       |
| `summary`          | `"Zero-fee Hyperledger Besu JSON-RPC government blockchain."` |
| `endpoints.length` | `70`                                                          |

Every endpoint entry describes `POST /` with no URL parameters. Its required
body fields are `jsonrpc: "2.0"`, `method: string`, `params: array`, and
`id: number | string`; its catalog response is HTTP `200`, described as a
JSON-RPC result or error object. The catalog is descriptive metadata and is not
used to validate or dispatch client calls.
