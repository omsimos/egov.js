# Import packages and types

## Root import

**The root entry exports every service** for applications that prefer one public
module.

```ts
import { eGovAiApi, eGovSsoApi } from "egov.js";
```

## Service subpaths

**Subpath imports are recommended** because they communicate service boundaries
and give bundlers the smallest possible graph.

```ts
import { eGovSsoApi } from "egov.js/eGovSso";
import type { EgovSsoCitizenProfile } from "egov.js/eGovSso";
```

**Dedicated type subpaths remain available** for consumers that separate runtime
and contract imports.

```ts
import type { EgovSsoCitizenProfile } from "egov.js/eGovSso/types";
```

## Module formats

**ESM and CommonJS are both published** with matching declarations. The exports
map routes `import` to `.js` and `require` to `.cjs` while keeping private build
files inaccessible.

```js
const { eGovChainApi } = require("egov.js/eGovChain");
```

<Note>
  The package is marked **side-effect free**, allowing modern bundlers to remove unused services
  from production bundles.
</Note>
